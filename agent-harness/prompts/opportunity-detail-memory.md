# 商机详情页业务记忆

以下规则适用于每一条商机，不按客户名称、示例数据或特定商机 ID 区分。三星仅是展示和验证样例，不是特殊分支。

## 商机字段

- 始终读取当前请求中 `scope.opportunityId` 对应商机的最新授权上下文，不复用上一条商机的字段或结论。
- 商机字段以 `profile`、`contact`、`protection`、`health`、`contract` 和 `evidence` 为统一口径；仅展示上下文中真实存在的值，缺失项明确标为待补充，不猜测。
- 联系人姓名和联系方式继续遵守权限与脱敏规则；无权查看时不得从推进记录、信号或历史对话中反推。
- 阶段、预算、签约金额、合同编号、签约时间等高影响字段，以 CRM 当前结构化字段为准；推进文本或连接器信号只能作为证据，不能覆盖结构化事实。

## 商机推进进展

- 所有商机统一汇总签约信息、人工推进记录、AI/连接器推进记录、有效销售信号和最初报备上下文，不因客户名称不同而改变处理方式。
- 按实际发生时间倒序理解进展；同一事实重复出现时合并表达，不把同一条连接器信号既当作推进记录又重复列为新进展。
- 区分来源：人工填写标为销售更新，Agent 自动沉淀标为 AI/连接器，签约字段标为签约确认，初始需求标为报备上下文。
- 只有已确认需求、方案或报价变化、合同/签约进展、明确会议或交付排期、风险变化、公司主体或关键联系人更新，才算实质推进；寒暄、收到、协调过程和无结论讨论不算推进。
- 无结构化推进记录时，可以用当前阶段更新时间生成阶段摘要，但必须说明这是阶段状态摘要，不得虚构客户动作、沟通内容或具体时间。
- 回答“最新进展”时优先引用最新有效推进及其来源和时间；若无有效记录，明确说明尚未沉淀有效推进，并给出需要补充的信息。
- 详情页不得逐条复述实时信号。应按需求、方案、报价、签约、交付、风险和关键资料等主题合并，只保留少量关键进展总结。
- 商机字段或关键进展变化后，必须重新评估商机解读、赢单机会、风险提醒和下一步行动，不沿用更新前的静态结论。

## 通用性约束

- 禁止编写或遵循 `customerName === "三星"`、名称前缀匹配三星、固定 `opp11` 等客户特例。
- 新增字段、进展来源或展示规则时，应作用于全部商机，并继续受当前用户权限范围约束。
